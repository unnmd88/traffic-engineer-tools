# Оставшаяся работа по контракту монитора

## Сборка и жизненный цикл Application

- [x] Шаг 1: отделить сборку `Application::new(config, tasks)` от `spawn(self)`.
  Подготовить начальные задачи и их идентификаторы без сетевых обращений и
  фоновых задач. Добавить `RunningApplication` и клонируемый
  `ApplicationHandle`, перенести управление монитором в handle, обновить CLI.
- [x] Шаг 2: связать время жизни фоновых задач с владельцем выполнения.
  При `shutdown().await` ожидать завершения сценариев, таймеров перезапуска
  и обработчика передачи истории во внешний канал; при удалении владельца
  отменять внутренние задачи. Сохранение истории за пределами канала
  остаётся ответственностью потребителя.
- [x] Шаг 3: проверить сборку и контракт без UDP. Добавить проверки сборки
  вне Tokio, подписки до запуска, клонирования handle и завершения.
  Собрать остальные тесты через `--no-run`, выполнить форматирование и линт.

Конфигурации отдельных задач проверяются конструкторами ядра. Отдельный
`Result` для сборки приложения добавлять при появлении проверок уровня
приложения. Пустой набор задач допустим для последующей регистрации.

Текущая последовательность использования:

```rust
let application = Application::new(config, tasks);
let subscription = application.subscribe_with_snapshot();
let running = application.spawn();
let monitor = running.handle();

let snapshot = monitor.get_snapshot().await?;

running.shutdown().await?;
```

До запуска задачи находятся в `Idle`, их идентификаторы доступны через
`application.task_ids()`. После запуска публикуются `TaskAdded` и
`TaskStarting`; готовность сценария подтверждается `TaskStarted`.
Вызов `spawn` требует контекста Tokio. `ApplicationHandle` клонируется,
владение выполнением остаётся у `RunningApplication`.

Проверено: `make check`, Clippy для `tools-core` и `tctl` со всеми целями,
форматирование изменённых файлов, 13 тестов ядра и 5 тестов CLI без сокетов.
Все тесты обоих крейтов собраны через `--no-run`. UDP-тесты не запускались.

Принятые правила метаданных, событий и расширяемости публичных типов описаны
в [ARCHITECTURE.md](docs/ARCHITECTURE.md#результаты-события-и-snapshot).
