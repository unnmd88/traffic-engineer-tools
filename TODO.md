# План развития контракта monitor

## Порядок работы

Перед каждым шагом давать краткую сводку предстоящих изменений.
После реализации и проверок объяснять результат и останавливаться.
Только после пользовательского «ок» делать коммит и переходить
к следующему шагу. Не объединять несколько шагов без согласования.

Сборка и выполнение Application уже разделены в коммите `bc91189`.

## Принятые решения

- Выбор расписания повторяющегося запроса выразить через PollSchedule:
  `FixedRate { period }` и `FixedDelay { delay }`.
- Расписание принадлежит повторяющемуся сценарию, не глобальному TaskConfig.
- `limit` считает полные выполнения сценария. Полный запрос, включая все
  внутренние повторы, расходует одну единицу независимо от успеха или
  исхода NoResponse после таймаутов. `limit = 0` означает отсутствие лимита.
- Счётчик выполнений и проверку limit оставить на уровне задачи/монитора.
- Новую обёртку VersionedTaskConfig не вводить.

## Шаг 2. PollSchedule

- [x] Реализовать FixedRate: сроки образуют сетку `origin + n * period`
  на монотонных часах, длительность запроса не сдвигает сетку.
- [x] Реализовать FixedDelay: следующий запрос назначается через delay
  после завершения предыдущего полного запроса с его повторами.
- [x] Для FixedRate реализовать последовательное выполнение: просроченные
  старты пропускать и ждать
  ближайшей будущей точки сетки, без догоняющих запросов.
- [x] Сохранить FixedDelay по умолчанию в CLI: текущий interval задаёт delay.
  Для явного выбора добавить `schedule: fixed_rate` или `fixed_delay`.
- [x] Первый запуск ждёт полный period/delay. После resume FixedDelay ждёт
  полный delay, а FixedRate продолжает по ближайшему будущему сроку
  исходной сетки. Возобновление точно на границе ждёт следующего периода.
- [x] Удалить ограничение `interval >= attempt.budget()`. В обоих режимах
  длительность расписания должна оставаться положительной.
- [x] Проверить расписание виртуальным временем и исполнителем без сокетов:
  темп, задержка, пропуски, resume, отмена ожидания и полные запросы
  с таймаутами и повторами. Всего прошли 37 тестов без сокетов.
- [x] Обновить отображение расписания в CLI и собрать все тесты tools-core
  и tctl через --no-run. Проверить компиляцию, форматирование и Clippy.
- [x] Получить пользовательское «ок» на результат и выбранные правила шага 2.

монотонная сетка повторяющихся запросов не синхронизирует разные объекты.
