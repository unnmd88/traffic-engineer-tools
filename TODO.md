# Контракт событий монитора

## 1. Типизированные сбои сборки и этапы паники

- [x] Передавать `ScenarioBuildError` через `ScenarioReport::BuildFailed`
  в `EventData::BuildFailed` без преобразования в строку.
- [x] Добавить `ScenarioBuildError::Timeout` для таймаута подготовки сценария.
- [x] Добавить `PanicStage::{Build, Execution, Runtime}` и поле `stage`
  в `EventData::ScenarioPanicked`; передавать исходный текст паники в `reason`.
- [x] Сохранить текстовую диагностику в `Health`, политику перезапуска,
  фильтрацию поколений и порядок событий.
- [x] Добавить тесты типов ошибок, таймаутов и всех этапов паники;
  проверить сборку тестов через `--no-run`.
- [ ] Запустить тесты после разрешения пользователя; тесты с локальными
  сокетами пока не запускать.

## 2. Семантика метаданных

- [ ] Закрепить `seq` как последовательность всех событий экземпляра монитора,
  а `source` — как идентификатор этого экземпляра.
- [ ] Различить время формирования события `at` и время завершения исполнения
  `ScenarioExecution::finished_at`.
- [ ] Закрепить `revision` как актуальную ревизию конфигурации на момент события.
- [ ] Использовать `Option<Generation>`: `None` до первого запуска,
  `Some` для текущего или последнего запущенного поколения.
- [ ] Закрепить возможность новой `revision` с прежним `generation`
  в `TaskSpecUpdated`: эта пара не описывает конфигурацию прежнего исполнителя.
- [ ] Закрепить `TaskStarting::attempt` как номер попытки запуска после сбоя,
  с нуля и со сбросом после успешной подготовки; отделить от сетевых попыток.
- [ ] Закрепить `retry_in` как запланированную задержку перезапуска,
  который может быть отменён последующей командой.

## 3. Расширяемость публичных типов

- [ ] Добавить `#[non_exhaustive]` вариантам `EventData` с полями,
  чтобы допускать расширение их полезной нагрузки.
- [ ] Проверить расширяемость `ScenarioExecution` и публичных enum ошибок,
  входящих в контракт событий.

## 4. Согласование подписки со snapshot

- [ ] Сохранить компактные факты `TaskAdded` и `TaskSpecUpdated`;
  актуальное состояние получать через snapshot.
- [ ] Добавить в `MonitorSnapshot` источник и `next_seq`, получаемые вместе
  с состоянием в оркестраторе.
- [ ] Обеспечить последовательность: подписаться, получить snapshot,
  применять события начиная с его `next_seq`.
- [ ] Обрабатывать `RecvError::Lagged` в CLI: повторно читать snapshot
  и продолжать обработку событий.
