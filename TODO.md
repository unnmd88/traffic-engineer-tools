# Переход оркестратора на Scenario

Ближайший этап — шаг 3. Реализацию сценариев пока сохраняем в одном
`scenario.rs`, тесты — отдельно.

## 1. Заменить запуск исполнителя

- [x] В `spawn_worker()` брать актуальный `ProbeSpec` из задачи, преобразовывать
  его в `Scenario` и запускать `run()`.
- [x] Использовать преобразование как временный переходник, не заводить вторую
  сохранённую спеку.

## 2. Проверить управление исполнением

- [x] Проверить запуск, паузу, возобновление и остановку.
- [x] Проверить обновление спеки в активном и приостановленном состоянии.
- [x] Проверить пересоздание после ошибки из актуальной сохранённой спеки.
- [x] Сохранить фильтрацию отчётов по `Generation`.
- [x] Сохранить порядок последнего `ProbeExecuted` и последующего `TaskCompleted`.

Переходы рассмотрены по коду и покрыты регрессионными тестами. Исправлены
отсутствующий `TaskStarting` после обновления активной спеки и обработка
устаревших таймеров перезапуска: команда `Respawn` теперь содержит `Generation`.
Счётчик попыток рестарта сбрасывается при обновлении спеки и возобновлении
без живого исполнителя. Тесты собраны через `--no-run`; выполнение тестов пока
отложено.

Оркестратор по-прежнему отвечает за состояние задачи, историю и метрики.

## 3. Перейти на хранение Scenario

- [ ] Заменить `ProbeSpec` в `TaskConfig` и snapshot, адаптировать CLI.
- [ ] Удалить временный переходник: оркестратор клонирует сохранённый `Scenario`
  непосредственно перед запуском.

## 4. Перенести limit в TaskConfig

- [ ] Перенести лимит исполнений из `ProbeSpec` в `TaskConfig`.
- [ ] Сохранить применение лимита на стороне оркестратора.

Интервал и параметры сетевых попыток остаются внутри конкретного сценария.

## 5. Удалить прежнюю реализацию

- [ ] Удалить старый `Worker` и неиспользуемую логику работающих проб.
- [ ] Сохранить нужные типы запросов, результатов и ошибок.
- [ ] Собрать команды, отчёты и `Generation` в `scenario.rs`.
- [ ] Переименовать внутренние сущности согласованно:
  `ScenarioCommand`, `ScenarioReport`, `ScenarioHandle`, `spawn_scenario()`.

## Проверки и ограничения

- На каждом шаге проверять компиляцию и Clippy.
- Тесты пока только собирать через `--no-run`, без запуска UDP-тестов.
- Публичные события на этом этапе сохранять.
